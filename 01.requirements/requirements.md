# 需求规格说明

## 1. 目标与范围

系统用于集中管理书籍基础信息、馆藏索书信息、评分、分类以及借阅/阅读状态。当前范围为单用户管理后台，不包含登录鉴权、权限管理、批量导入、外部图书服务同步和统计报表。

## 2. 用户与使用场景

唯一角色为书籍管理员，可完成：

1. 按书名、评分区间、借阅属性、分类和等级组合检索书籍。
2. 分页浏览书籍，并查看书籍完整信息。
3. 新增书籍；书名和索书号必填。
4. 修改任意书籍字段。
5. 删除书籍。删除采用逻辑删除，已删除数据不再出现在查询结果中。
6. 获取现有类别和小类别，用于前端筛选项。

## 3. 功能需求

| 编号 | 功能 | 验收标准 |
|---|---|---|
| FR-01 | 书籍列表 | 默认第 1 页、每页 20 条，按 ID 倒序，返回列表和总数 |
| FR-02 | 条件查询 | 支持书名模糊匹配，其余筛选字段精确匹配，评分支持闭区间 |
| FR-03 | 单本查询 | 有效 ID 返回书籍；不存在或已删除返回 HTTP 404 |
| FR-04 | 新增书籍 | 合法数据落库并返回新 ID；缺少必填字段返回 HTTP 422 |
| FR-05 | 编辑书籍 | 支持部分字段更新；不存在或已删除返回 HTTP 404 |
| FR-06 | 删除书籍 | 将 `is_deleted` 置为 `Y`；重复删除返回 HTTP 404 |
| FR-07 | 分类选项 | 仅返回未删除书籍中非空且去重的类别/小类别 |
| FR-08 | 服务状态 | `/` 返回服务信息，`/health` 返回健康状态 |

## 4. 数据规则

- `book_name`：必填，最长 255 字符。
- `call_number`：必填，最长 200 字符。
- `isbn`：可选，最长 50 字符。
- `douban_score`：可选，取值 0 到 10。
- `remark`：可选，备注文本，无长度限制。
- `category`、`sub_category`：可选，最长 100 字符。
- `level`：可选，整数等级。
- `normal_loan`、`reference_loan`、`wechat_read`、`borrow_status`、`is_deleted`：数据库使用 `Y/N`。
- `page >= 1`，`1 <= page_size <= 100`。

## 5. 非功能需求

- API 使用 JSON，业务成功响应统一为 `code=0`、`message=success`、`data`。
- MySQL 使用 `utf8mb4`，支持中文书名和备注。
- 前后端可使用 Docker Compose 部署。
- 数据库凭证只能通过环境变量注入，禁止写入仓库。
- 后端测试不得依赖生产数据库，必须可重复、相互隔离；前端测试不得依赖真实后端服务，所有网络请求均需 mock。
- 后端与前端测试覆盖率均需达到 100%（语句、分支、函数、行）。

## 6. 当前限制

- 当前没有用户认证和访问控制，不应直接暴露在不受信任的公网环境。
- 删除为逻辑删除，当前没有恢复或物理清理接口。
- 健康检查只表示 API 进程可响应，不验证数据库连通性。
